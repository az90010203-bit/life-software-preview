# 人生软件 · 模块桌面交互预览

[打开在线预览](https://az90010203-bit.github.io/life-software-preview/)

这是人生软件的模块桌面交互预览。使用原创观景室场景和圆润 SVG 图标，验证自由布置的个人空间。

界面采用银白薄面板和圆润控件。观景室固定镜位，窗外云层缓动、舰船随机经过，夜间有低频流星。
右上角「场景设置」提供动态、随机景象及自动／固定时段选择，背景不压暗。
清晨 05–08、白天 08–17、黄昏 17–19、夜晚 19–05 跟随设备当地时间，边界前后各十分钟平滑混合；
手动切换约 1.5 秒。夜间改变窗外光色与城市灯火，插件保持浅色阅读面。

界面字体统一为 HarmonyOS Sans SC（鸿蒙 Sans）。Regular 和 Medium 使用华为官方字体包中的原始 TTF，
未做字体修改或子集化，随网站加载；原始许可位于 `public/fonts/HarmonyOS-Sans-LICENSE.txt`，
页面说明内提供字体署名和许可入口。来源：https://developer.huawei.com/consumer/cn/design/resource-V1

进入「布置空间」后，可以拖动组件标题栏、靠近边缘或其他组件吸附、拖动卡片或面板右下角调整大小，
并切换图标／卡片／面板。组件库可以添加同类组件的多份实例；收起仅移除桌面实例，
业务内容保留，移除后可以撤销。空桌面会保持为空，不自动重新添加组件。

随手记、月历和今日重点已按统一接口接入为三个内置插件。同类实例共享记录，位置、尺寸和显示方式分别保存。
布局与场景偏好保存在 localStorage；三个插件的记录、事项和草稿保存在当前浏览器的 IndexedDB，不同电脑之间尚未同步。
手机按列表显示，保留电脑的归一化布局坐标。

当前尚未实现原生插件宿主、外部插件包安装／升级、Rust／SQLite 存储、云同步和 AI。
GitHub Pages 仅托管前端，不托管个人记录或本地数据库。

## 布局层与业务层

桌面以「功能模块 → 显示形态 → 桌面实例」分层。组件注册表声明名称和各形态尺寸，
桌面实例只保存实例 ID、模块类型、形态、归一化坐标、像素尺寸和层级；不携带业务记录。
布局内核独立管理恢复、校验、创建、形态切换和吸附。插件通过平台的数据服务管理业务内容，
拖动不会重新挂载实例，收起或变换形态也不删除已保存内容。

## 插件接入接口 v1

`src/platform` 提供通用插件接口、注册校验、视图宿主、渲染错误隔离和数据保存能力。
`src/plugins` 下每个插件独立提供声明、Provider 和视图；桌面不再按具体业务类型分支渲染。

一个内置插件提供 `PluginDefinition`：

- `manifest`：稳定 ID、接口版本、插件版本、名称、描述、图标、三种形态尺寸及最小面板尺寸。
- `Provider`：可选封装插件内部的状态与业务操作，内置插件通过共享数据服务读取同一份记录。
- `View`：接收 `mode` 和 `instanceId`，呈现卡片或完整面板；图标形态由平台统一绘制。
- `Status`：可选的底栏状态。`manifest.quickAction` 可选声明快捷操作，视图用 `data-plugin-focus` 标记需要聚焦的输入。

新增插件时建立自己的目录，在 `src/plugins/index.ts` 注册定义即可；组件库自动发现注册列表。
同一文件还声明初始桌面构成。外部包动态加载、停用／卸载管理和不可信代码沙箱不属于当前实现。
当前注册的是随应用构建的可信内置插件，数据按命名空间分区，并不构成第三方代码的安全隔离。

`usePluginState` 继续供简单独立插件使用。三个内置插件改用 `src/data` 的 TaskService 和 React 订阅：
笔记独立保存，月历与今天引用同一事项 ID；重点顺序按本地日期记录，最多三件（包括已完成事项）。
新增、改期和重点替换通过 IndexedDB 事务提交，跨标签通过 BroadcastChannel 通知重读，缺失时使用 storage 通知。
修改同一条内容时校验 revision，冲突保留草稿，可保存副本或采用最新内容。跨标签草稿隔离，刷新恢复；
存储失败不清空输入、不声称已保存。更多菜单可导出全部插件数据、未保存草稿与旧数据原文。

首次按插件分别迁移原 localStorage 命名空间，原数据只读保留。旧月历文字仍是当天备注，旧今日文字成为
对应日期的一件重点。迁移内容与标记在同一事务中提交，刷新不重复导入；部分损坏保留有效条目并提示，
不会阻止其他健康插件的迁移。数据库不可用时不静默切回另一套持久存储。

`openPlugin(id, target)` 打开并定位已有插件实例，必要时新增实例，不进入布置模式；插件不直接访问彼此的内部状态。

## 三个插件的日常使用

- 随手记无需标题，支持 Ctrl／⌘+Enter 收好、全文搜索、按本地日期分组、原位编辑、长文展开、删除撤销与恢复。
  新建和编辑草稿分别保留。片段可主动转成安排或今日重点，原文保留，后续不自动同步笔记文字。
- 月历按天添加多件事项，时间与详情选填。点击空日期在月历下方整宽输入，事项可完成、编辑、改期及恢复。
  当天先显示未完成事项，有时间的按时间排列，无时间的按创建时间排列；卡片同时展示今天与下一件未来事项。
- 今天最多放三件重点，可完成、编辑、调序、移出及替换；移出重点不删除事项。完成状态和标题与月历共享。
  旧重点由用户手动带到今天，跨日不自动搬运；其他日期的事项加入今天前需确认改期。

删除采用可恢复方式，不自动清空最近删除；恢复事项不自动占用重点位置。本轮没有重复任务、系统提醒或云同步。

未知插件的已有布局仍保留为占位，避免临时移除代码时丢失位置；重新注册同一 ID 即可恢复视图。
移除桌面实例不删除插件数据。后续原生数据库接入可替换保存适配层。

```powershell
npm test
```

测试覆盖插件注册与布局保留、旧数据迁移及损坏保护、并发三件限制、事务回滚、冲突草稿、跨标签修改、
删除恢复、改期联动、存储失败导出、排序、检索与本地时区日期分组，以及动态场景调度。
GitHub Actions 在构建发布前执行这些测试。

## 场景内容包 v1

`src/scene` 提供独立于业务插件的内容注册、时钟、设置和事件调度。内容包声明原画尺寸、窗外与城市遮罩、
素材、灯光／星点、航线和事件；注册时校验航线引用与基础参数。新增可信内置场景包后加入注册表，
即可复用运行时；当前只开放观景室。尚无外部场景安装与下载管理。

所有图层在同一个原画坐标系内统一缩放与裁切。远处航行受城市遮挡，所有舰船与云层受窗框遮挡。
主体事件首次等待 20–40 秒，之后每次驶离再等 120–240 秒，权重和冷却控制种类；同屏最多一个主体。
输入时现有舰船继续驶离，停止安排新事件；退出输入重新等待。布置和页面隐藏冻结动画及事件时间，
返回后校准现实时间，不补播。系统减少动态设置优先于用户动态偏好。

场景偏好单独保存在 `life-preview.scene-settings.v1`，首次兼容旧 `life-preview.scene-motion.v1` 开关。
场景不读取插件业务数据。媒体失败时保留静态原画；存储不可用时偏好保留于当前页面。

两款透明舰船由内置 image_gen 生成，原图与来源说明保存在 `public/art/scene-v1/`。
首轮唯一一段 TAPNOW 5 秒 draft 云海样片已检查：镜头和建筑漂移、普通循环有接缝，因此不用于正式背景。
样片、完整提示词与检查记录保存在本机 `output/scene-v1/`，未自动追加收费生成。
正式版本使用独立透明云海绘画，按远近两层匀速平移循环，云的纹理和轮廓会实际移动；城市和窗框固定。
云层素材、位置、速度和透明度由内容包声明，手机保留一层。关闭动态或进入布置时冻结当前位置。
内容包保留可选静音视频层，加载失败或播放被拒绝时回退。

场景自动测试覆盖当地时段及过渡、随机权重和夜间限制、冷却、输入／隐藏／布置状态、设置兼容和新内容包注册。

## 技术

React、TypeScript、Vite。GitHub Actions 构建并部署到 GitHub Pages。
后续平台计划接入 Tauri、Rust、SQLite 和可独立安装的网页模块包。

## 本地开发

```powershell
npm ci
npm run dev
```

默认地址为 `http://127.0.0.1:4317/`，端口占用时直接退出。
本地开发模式提供只读的 `/__preview/health`，返回服务时间，禁止缓存。
`scripts/Start-Preview.ps1` 和 `scripts/Stop-Preview.ps1` 可以管理本机后台预览。

如果使用私有反向代理，可以通过 `LIFE_PREVIEW_ALLOWED_HOST` 精确允许额外主机名。

## 静态构建

```powershell
$env:PAGES_BASE_PATH = '/life-software-preview/'
npm run build:pages
```

输出位于 `dist/`。静态模式使用仓库子路径加载资源，并生成 `preview-status.json`，
记录页面构建时间，不连接开发电脑或本地数据库。

## 自动部署

推送到 `main` 后，`.github/workflows/pages.yml` 安装依赖、检查 TypeScript、构建网页并部署。
仓库的 GitHub Pages 发布来源设置为 GitHub Actions。

本项目不包含个人记录、访问凭据或数据库备份。
